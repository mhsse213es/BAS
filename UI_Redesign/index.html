Design proposal · v0.3 · 31 Oct 2026 · draft for review

A console that tells a bank how secure it is, at a glance

A redesign of the Audspect console so a CISO can read the organisation's security posture in five seconds, an analyst knows what to fix next, and an auditor gets signed evidence. It is built on one design system, one navigation model and one set of metric definitions.

Open the new dashboard Design system Decisions for discussion

One number, then the why

A single posture score (higher is always better) with a band, a target and a plain-language summary, followed by the drivers: kill chain, control domains, threats, compliance and fix-first actions.

27 menu items become 15

Navigation is grouped by job (Validate, Analyze, Remediate, Govern, Manage). Every page uses the same anatomy, the same table and detail panel, and the same status language.

Built on what Audspect already has

Most of the dashboard is served by existing APIs. The biggest gap, “posture by control domain”, is already built in the backend (/api/controlhealth/summary) and simply unused.

New in v0.3 (from your “too many boxes / nothing at a glance” review): the dashboard is rebuilt around one focal point — a radial posture gauge with a plain-language verdict and the four numbers that matter — and then just the module scores as a single ranked chart (not a grid of tiles), the three fixes, one trend, and a “go deeper” launchpad to the detail pages. The whole thing is now about half the length and readable in five seconds. Across every page the hard card borders are gone — content floats on whitespace instead of sitting in boxes. (v0.2 added the softer palette and per-module scores; v0.1 set up the IA and page set.)
How to review. Open the pages in order. On any page press N to show the numbered design notes; each note covers why the element exists, which API feeds it, what it replaces today and what it needs to be built. Press T to switch theme, or add ?theme=light to a URL. The sidebar, command palette (Ctrl K), notifications and account menus are all live. All data is fictional (“Contoso Bank”). 01Why the console feels “all over the place”

Taken from a read-only audit of orchestrator/web and the API routes on main. The product has a lot of capability; the problem is breadth without hierarchy, the same concept living in several places, and numbers that disagree.

27sidebar items in 4 loose groups, reaching 30 pages, plus 10 Settings sections
~25 + 17cards and tiles on one dashboard scroll; only 4 of 16 rows have headings
~15differently defined scores, some “higher is better”, some “higher is worse”
12+API calls and 3 polling timers per dashboard load, with most maths done in the browser
51modals and drawers, from 520 px to full width, with up to 12 tabs inside a drawer
7+tab styles, 3 table behaviours and 3 icon styles (including emoji)
838 + 833raw inline styles in JS, plus uses of 439 one-off generated classes
301hard-coded colours from two palettes, 67 font sizes and 14 radii, with no spacing or type scale

Same concept, many places

  • Coverage appears in 5 places and run lists in 6.
  • Scheduling is in 4 places, threat intel in 6 and integrations in 3.
  • Compliance, the headline of the login page, has no sidebar entry.
  • Board scorecard and Navigator exports are hidden in each agent's row menu.
  • “Soon / not available” placeholders appear where the backend already works (report schedules, Navigator export).

Numbers that mislead

  • The two dashboard views show two “posture” scores pointing in opposite directions.
  • “ATT&CK coverage” is really a prevention share, and “Detection rate” is prevented + detected.
  • Fleet compliance tiles show the worst agent, and readiness widgets use only the first agent; neither is explained.
  • The executive exposure trend is coloured backwards (a rise is shown as bad, but higher is safer).
  • “Updated hh:mm:ss” is the time the page opened, not the age of the data.

Air-gapped operation, offline signed content bundles and no telemetry leaving the bank. Shown in the UI, not hidden.

BFSI compliance native

RBI, SEBI CSCRF, CERT-In and IRDAI sit next to PCI DSS, ISO 27001 and NIST CSF, mapped to evidence.

Tamper-evident evidence

Signed reports and audit packs that an auditor can verify independently.

Local threat context

Default threat profile for Indian banking, with group readiness that is relevant on day one.

03Design principles

1 · Five-second answer

Every overview page answers its main question above the fold: how secure, which direction, what to do next.

2 · Every number is a link

KPIs open the evidence behind them. Each metric has one definition, written once and reused in tooltips and reports.

3 · One direction

Scores are always “higher is better”. Risk-style numbers are converted, never mixed on one screen.

4 · Same anatomy everywhere

Page header → one filter row → content → detail panel. Same table, same status words, same buttons.

5 · Honest states

“No evidence yet” instead of 0% or 100%; real data freshness; unknown detection is never shown as missed.

6 · Dark-first, print-perfect

A navy dark theme matching the logo, a light theme for executives and print, and WCAG AA contrast computed for every token.

04Information architecture: 27 items become 15

The sidebar is grouped by the job the user is doing. Add-ons and attack vectors become assessment types or coverage views instead of separate menu items. Every old tab id keeps working as a route alias, so the 24 tab ids in the smoke tests and existing bookmarks still resolve.

05Pages in this proposal

Each page is a working, clickable HTML mock-up built only from the shared design system in assets/. Hover charts for values, use the table toggle on every chart, and press N for design notes.

01Design system

Tokens for both themes with computed contrast, type and spacing scales, components, chart rules, status language and the token migration table.

02Security posture dashboard Key page

Executive view (score, KPIs, trend, fix-first, kill chain, control domains, ATT&CK, threat groups, attack paths, compliance) and an Operations view.

03Assessments

One list for runs, schedules, campaigns, emulations and re-tests, a run detail panel and the four-step “New assessment” flow.

04Findings

Prioritised findings with severity, SLA and owner. The detail panel shows evidence, vendor-specific fixes and re-test to verify.

05ATT&CK coverage

The full matrix for the active threat profile, technique detail and threat-group readiness, plus Navigator export.

06Compliance

Seven frameworks, control-level status backed by evidence, an explicit aggregation rule and signed, verifiable reports.

07Endpoints

Fleet health, posture per endpoint, a detail panel and a guided, secret-safe agent deployment flow.

08Reports

Report centre for board, executive, compliance, technical and Navigator outputs; schedules and signature verification.

09Module detail New

One template behind every module tile: score, trend, KPIs, results by test and the open findings for that module.

10Threat library

Scenario catalogue — group emulations, packs, technique sets and custom scenarios — with a detail panel.

11Purple-team exercises

Live red-vs-blue timeline, detection scorecard and conversion of missed steps into findings.

12Detection validation

Expected vs fired alerts per SIEM/EDR, silent failures and rule-level results with time-to-detect.

13Attack paths & exposure

Paths to crown jewels, the choke points that break the most paths, and the exposure explorer.

14Threat intelligence

Threat groups, what to test next, KEV exposure validated by simulation, and the IOC registry.

15Remediation plans

Findings grouped into owned initiatives with projected uplift, plus the SLA report.

16Integrations

Every connector — SIEM, EDR, ITSM, threat intel, engine — in one place with health states.

17Settings

Users & roles, SSO, audit log, licence, content, backup, appearance and notifications.

00Sign in

The entry screen: SSO-first, with local break-glass access and the on-prem positioning.
