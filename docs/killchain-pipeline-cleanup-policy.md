# Pipeline test-record tagging and cleanup policy (proposal)

Status: proposal. Nothing in this document is implemented. Cleanup and injection stay
disabled until this policy is accepted.

## Why this exists

A future injection stage will create test events and cases in a customer SIEM or ticketing
system. Cleanup must never remove a record that was not created by the test run. Audit
records are legitimate evidence, so they are never deleted by cleanup.

## Rules

1. **Test-run identifier.** Every injection run gets a unique identifier, generated by the
   server, stored with the approval record. It is never supplied by the caller.
2. **Marker.** Each generated event or case carries the identifier and a fixed marker
   (for example a field `audspect.test_run` and a tag `audspect-bas-test`). The marker is
   written at creation, not added afterwards.
3. **Cleanup selects by identifier only.** Cleanup queries records that carry the exact run
   identifier. A record without the identifier, or with a different one, is never selected.
   Wildcards and time-window-only selection are refused.
4. **Provider capability.** A provider's cleanup is supported only if it can select test
   records by the marker reliably. If it cannot, the stage reports cleanup as UNSUPPORTED,
   the records are retained, and the retention is shown to the operator. Nothing is deleted
   on a best-effort basis.
5. **Audit records are never deleted.** Audit, log and access-trail entries are excluded
   from cleanup regardless of marker. Only records the platform created as test artefacts
   (events and cases) are candidates.
6. **Retention.** Test artefacts are kept for a defined window (proposed: 30 days), then
   removed by the scheduled cleanup, unless an operator has retained them with a recorded
   reason.
7. **Deletion permission.** Cleanup requires the same approval as injection. The approver
   must differ from the operator who ran the test where the deployment enforces separation
   of duties. Each deletion is recorded with the identifier, the record IDs, the approver
   and the outcome.
8. **Failure is visible.** A partial cleanup is reported with the records that remain.
   It is never reported as complete.

## Open decisions for the owner

- Retention window (proposed 30 days).
- Whether single-person approval is acceptable for cleanup in lab deployments.
- Which providers support marker-based selection. This is determined per connector during
  its read-only adapter work, not assumed.
