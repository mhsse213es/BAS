## S10: API reachability from a workload namespace. Result: PASS (blocked)

| Probe | Target | Expected | Observed |
|---|---|---|---|
| anonymous | https://kubernetes.default.svc/api/v1/namespaces | refused (401 or 403) | HTTP 403 |
| default service account token | same | refused (401 or 403) | HTTP 403 |

Both probe pods were removed and the removal confirmed. Probe image: curlimages/curl:8.11.1.

Earlier attempt, for the record: the busybox wget image failed the TLS handshake with the API server (alert 40),
so no HTTP status was returned. The check was changed to curl. This was a probe-tool problem, not a finding.

## S9: cross-namespace pod-to-service reachability. Result: FAIL, not a valid result yet

| Probe | Target | Expected | Observed |
|---|---|---|---|
| blocked port | db.np-db.svc.cluster.local:3306 | CLOSED | CLOSED |
| allowed port | db.np-db.svc.cluster.local:5432 | OPEN | CLOSED |

Cause: the lab fixtures create no Service named db in np-db and no process listening on 5432 or 3306. DNS fails and
the connection is refused whatever the policy says, so this run cannot tell a working policy from a missing
service. A valid S9 needs a Service and a listener on 5432 (and a listener on 3306 so the blocked port can be
shown to be blocked by policy, not by absence). That is a change to the lab fixtures and is not made here.
