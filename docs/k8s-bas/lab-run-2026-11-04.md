## S9: cross-namespace pod-to-service reachability. Result: PASS (blocked)

| Probe | Target | Expected | Observed |
|---|---|---|---|
| blocked port | db.np-db.svc.cluster.local:3306 | CLOSED | CLOSED |
| allowed port | db.np-db.svc.cluster.local:5432 | OPEN | OPEN |

Setup added for this run: lab-listener.yaml (a pod labelled app: db in np-db that listens on 5432 and 3306, and a
Service named db routing to it). Both ports were confirmed LISTENING inside the pod before the probe ran, and still
were afterwards.

Earlier attempts, for the record:
- Before the listener existed, both ports read CLOSED. That result was about the missing service, not the policy.
- The first listener used one `nc -lk` per port. busybox nc exits after one connection, so the 5432 listener died
  after the first probe. The listener now restarts after each connection.

Note on enforcement: 3306 has a live listener and is still CLOSED from np-app, so the NetworkPolicy is what blocks it.
The cluster uses kindnet. Whether kindnet enforces NetworkPolicy in general is not confirmed by this run alone; it is
confirmed only for this flow.
