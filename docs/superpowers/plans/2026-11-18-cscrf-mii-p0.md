# CSCRF-MII P0 Control Validation Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Correct the nine existing `cscrf-mii-drill` steps where their claim is wider than their test, then add the P0 control-validation packs: network and infrastructure, identity and privileged access, endpoint and audit integrity, and the SIEM telemetry pipeline.

**Architecture:** The drill keeps its id `cscrf-mii-drill` (referenced by `execclass.go`, `verdict_token_test.go` and the coverage matrix), so its nine steps are corrected in place, re-signed, and their classes checked. New control domains are generated packs with their own ids, following the Cobalt pattern. Each step is tiered (configuration check, active test, or end-to-end), and state-changing steps are active-tier only, lab-gated, with verified undo.

**Tech Stack:** PowerShell scenario scripts, `appctlgen`, `signer.go`, Go (`internal/scenario`, `internal/scenario` classification tests).

**Spec:** `docs/superpowers/specs/2026-11-18-cscrf-mii-control-validation-design.md`

## Global Constraints
- `appctlgen -common <pack's own dir>` passed explicitly every time.
- `product_line` on every new header must be valid: use `common` for the drill (already) and `killchain` only where the pack is an attack-path pack. CSCRF control packs use `common`.
- Never name a variable `$Host`/`$host`.
- Sign with `orchestrator/scripts/signer.go`, never cosign.
- Mapping labels are internal references (`CSCRF-*-NN`), never SEBI clause identifiers.
- Production-safe steps are read-only. Any step that changes state needs an explicit env gate and a live-verified undo.
- Every new `action_key` needs an explicit catalog class before its scenario is signed (see the classification test pattern in `execclass_bfsi_test.go`).
- Full unfiltered `go test ./internal/scenario -count=1 -timeout 420s` before any commit is called done.

## Review Focus
- **Silent PASS on a missing control:** a configuration check must FAIL when the setting is absent, not PASS.
- **Read treated as modification:** audit-policy enumeration must be read-only; a test of modification is a separate active step.
- **Log clear success vs attempt:** the log-clear step must report whether the log was actually cleared, not just that the command ran.
- **Account left behind:** the account create/delete step must verify both events and removal.

**Interfaces:**
- Consumes: `signer.go sign` and `verify-all`.
- Produces: the corrected drill, still id `cscrf-mii-drill`.

- [ ] **Step 1: Read the nine steps** and record, for each, what the step actually proves against what its name claims (the proposal's correction table is the starting point).
- [ ] **Step 2: Rename and re-describe each step** so its name states what it tests:
  - Management Port Scan becomes "Localhost management-port reachability (not perimeter)".
  - Failed Auth Probe becomes "Failed-logon telemetry probe against a nonexistent account (no password guessing)".
  - Audit Policy Enumeration becomes "Audit policy read (no modification)".
  - Local Group Enumeration becomes "Local group membership read".
  - WinRM probe becomes "Localhost WinRM reachability (not lateral movement)".
  - Log clear becomes "Security log clear attempt, with outcome recorded".
  - SYSTEM task becomes "SYSTEM scheduled task create and delete, with execution context recorded".
- [ ] **Step 3: For the log-clear step,** make the verdict distinguish attempted from successful: PASS only if the clear was blocked, FAIL only if the log was actually cleared, and SKIP with a reason if the env gate is not set.

- [ ] **Step 5: Run the drill's steps live** on this host with the lab gates off, then with them on for the lab-only steps, and record each verdict.
- [ ] **Step 6: Re-sign and verify** with `signer.go sign` and `verify-all`, expect fail=0.

### Task 2: P0 network and infrastructure pack

**Files:**
- Create: `scenarios-src/cscrf-mii-network/{header.yaml,stages.json,lib.ps1,net-01..net-08.ps1,net-01..net-08.undo.ps1}`
- Create (generated): `scenarios/cscrf-mii-network.yaml` and `.yaml.sig`
- Modify: `orchestrator/internal/scenario/execclass.go` (classes for new action keys)

**Scenarios (internal references):**
- net-01: non-local service discovery on an authorized lab subnet (T1046), read-only, gated by `BAS_LAB_SUBNET`.
- net-02: firewall rule enumeration (T1016), read-only.
- net-03: firewall policy modification detection (T1562.004). Configuration check only on production; active modification only in the lab gate, with undo.
- net-04: unnecessary listening-service detection (T1046), read-only.
- net-05: DNS resolver configuration validation (T1016), read-only.
- net-06: segmentation enforcement test. Configuration check until a second zone exists (`BAS_ZONE2_TARGET`), then an active connection attempt across zones.
- net-07: unauthorized inbound connection attempt against a lab target (gated).
- net-08: unauthorized outbound connection attempt to a reserved `.test` or `.invalid` endpoint, which cannot reach a real destination.

- [ ] **Step 1: Write `header.yaml`, `stages.json` and `lib.ps1`** with the standard verdict and undo helpers, tag prefix `BAS-NET-`, and gate helpers that read `BAS_LAB_SUBNET`, `BAS_ZONE2_TARGET`.
- [ ] **Step 2: Write each step and its undo.** Read-only steps have no-op undos. Net-03's lab-gated modification must record the original rule and restore it, and its undo must verify restoration.
- [ ] **Step 3: Live-run each step** on this host, with gates off (SKIP expected for gated steps) and with gates on for net-03 in the lab. Verify undo leaves the firewall rule as it was.
- [ ] **Step 4: Add catalog classes** for each new action key in `execclass.go`, following the BFSI test pattern, and update the embed pins.
- [ ] **Step 5: Generate, sign, verify.**
- [ ] **Step 6: Commit** after the full suite passes.

### Task 3: P0 identity and privileged access pack

**Files:**

**Scenarios (internal references):**
- id-01: privileged group membership change (T1098). Lab-gated, synthetic account in a non-admin group only, undo verified.
- id-02: local administrator account creation (T1136.001). Lab-gated, synthetic account, removed by undo.
- id-03: privileged account login monitoring (T1078). Read-only check of recent privileged logons.

- id-07: MFA enforcement validation. Configuration check only; SKIP without an identity provider endpoint.
- id-08: service account privilege assessment. Read-only check of service accounts with interactive or admin rights.
- id-09: remote privileged login validation (T1021). Lab-gated, localhost-only until a second host exists.

- [ ] **Step 1: Write the pack** following Task 2's layout.
- [ ] **Step 2: Each lab-gated step** verifies its change and undo before PASS, so a failed undo is never reported as clean.
- [ ] **Step 3: Live-run**, with lab gates off and on, and record verdicts and residue checks (accounts, group memberships).
- [ ] **Step 4: Catalog classes, generate, sign, verify, commit.**
