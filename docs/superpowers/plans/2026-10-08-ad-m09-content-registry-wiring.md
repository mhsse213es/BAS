**Goal:** Give AD-M09 ("AD Threat Content Factory") its registry wiring only, exactly as scoped by the user: map an AD primitive's metadata into `contentregistry`'s existing intake/lifecycle/provenance model as a DRAFT/LOCAL stub referencing a future (not-yet-authored) scenario artifact, and prove the wiring with tests against the real registry. Explicitly NO executable commands, NO new attack steps, NO exploit implementation, NO procedural technique content — actual scenario authoring is a separate future project, dependent on M06 and the safety/execution architecture.

**Architecture:** New package `orchestrator/internal/adcontent`, depending one-way on `adprimitive`, `scenario` (for `IntakeFile`/`IntakeDecision`/`Scenario`/`Step` types only), and `contentregistry` (for `Registry`/`SourceIntel`). `StubIntakeFileFor(p adprimitive.Primitive) (scenario.IntakeFile, bool)` builds a minimal, valid `scenario.Scenario` YAML with `ID`/`Name`/`Description` set from the primitive and an EMPTY `Steps` slice — `analyzeArtifact` (the registry's own parser, already read) only requires a non-empty `ID` to accept an artifact; it never requires steps. `Register(ctx, r *contentregistry.Registry, p adprimitive.Primitive) (scenario.IntakeDecision, error)` calls `r.Intake` with `Source: "intel"` (`contentregistry.SourceIntel`'s string value), which the registry's own existing logic routes to `Trust=Untrusted, Lifecycle=Draft, Actor=generator:connector` — already-built semantics for exactly this "automated content generation" case, requiring zero new registry logic.

**Tech Stack:** Go (matches `orchestrator`'s existing stdlib-only + `gopkg.in/yaml.v3` convention already used by `contentregistry`; no new dependencies). Tests use the existing `testutil.MustSharedTestDB()` Postgres-backed harness `contentregistry`'s own tests already use (Docker confirmed running).

**Spec:** No separate written spec document — bounded, conversationally-approved task. The user fixed this exact scope after flagging that "AD Threat Content Factory" by name implies executable-content generation: registry wiring ONLY, stub content referencing a future artifact, no technique/command content of any kind.

## Global Constraints

- Go stdlib + existing `gopkg.in/yaml.v3` only — no new dependencies.
- `go 1.26.6`, module path `github.com/audspect/bas`.
- The generated stub artifact's `Steps` field is ALWAYS empty (`nil`/zero-length) — this plan contains no code path that ever populates a step, a command, or a technique-execution detail of any kind.
- No field is added to `contentregistry`'s types, no new `IntakeSource`/`Lifecycle`/`Trust` value is added, and no change is made to `Intake`'s own routing logic. This phase registers content THROUGH the existing `SourceIntel` path, unmodified.
- No field is added to `adprimitive.Primitive`.

## Review Focus

- A primitive with an empty `ID` must make `StubIntakeFileFor` return `ok=false` — the registry's own `analyzeArtifact` fails closed on a missing `id` field, and this plan's stub builder must fail the same way before ever reaching the registry, not rely on the registry to catch it. Tested in Task 1, Step 1.
- Registering the SAME primitive twice (same `ID`, same generated bytes) must be idempotent — `Intake`'s own hash-based dedup means a second call with identical bytes returns `Accepted: true` without creating a second version, not an error and not a duplicate row. Tested in Task 1, Step 1 (DB-backed).
- The registered version's `Lifecycle`/`Trust`/`Source` must be exactly `Draft`/`Untrusted`/`SourceIntel` — these are the registry's own pre-existing routing rule for intel-sourced content, and a wiring bug (e.g. passing the wrong `Source` string) would silently route to a different, wrong lifecycle. Tested in Task 1, Step 1 (DB-backed).

```go
// orchestrator/internal/adcontent/register.go

// Package adcontent bridges AD-M09 ("AD Threat Content Factory")
// registry wiring ONLY into the existing contentregistry intake
// pipeline. It registers a minimal metadata stub (id/name/description,
// always zero Steps) as intel-sourced DRAFT content, referencing a
// future, not-yet-authored scenario artifact. It contains no executable
// commands, no attack steps, and no technique-execution content of any
// kind -- actual scenario authoring is a separate future project.
package adcontent

import (
	"context"
	"fmt"

	"gopkg.in/yaml.v3"

	"github.com/audspect/bas/internal/adprimitive"
	"github.com/audspect/bas/internal/contentregistry"
	"github.com/audspect/bas/internal/scenario"
)

// StubIntakeFileFor builds a minimal scenario.IntakeFile for p: a valid
// scenario.Scenario YAML with ID/Name/Description set from p and an
// always-empty Steps field. Returns ok=false when p.ID is empty --
// contentregistry's own intake parser requires a non-empty id, and this
// builder fails the same way before ever reaching the registry.
func StubIntakeFileFor(p adprimitive.Primitive) (scenario.IntakeFile, bool) {
	if p.ID == "" {
		return scenario.IntakeFile{}, false
	}
	desc := fmt.Sprintf("AD-M09 registry stub for primitive %q -- no scenario artifact authored yet.", p.ID)
	sc := scenario.Scenario{
		ID:          p.ID,
		Name:        p.Name,
		Description: desc,
	}
	raw, err := yaml.Marshal(sc)
	if err != nil {
		return scenario.IntakeFile{}, false
	}
	return scenario.IntakeFile{
		Path:   "ad-m09-stub/" + p.ID + ".yaml",
		Source: string(contentregistry.SourceIntel),
		Artifact: raw,
	}, true
}

// Register builds p's stub intake file and submits it to r, registering
// it as intel-sourced DRAFT content.
func Register(ctx context.Context, r *contentregistry.Registry, p adprimitive.Primitive) (scenario.IntakeDecision, error) {
	f, ok := StubIntakeFileFor(p)
	if !ok {
		return scenario.IntakeDecision{}, fmt.Errorf("adcontent: primitive %+v has no ID, cannot build a stub", p)
	}
	return r.Intake(ctx, f)
}
```
