# Reports — Design Spec

**Date:** 2026-06-17
**Status:** Approved-with-changes (incorporates the `reports.txt` review)

## Purpose

A central **Reports** page: a hub to generate the evidence reports the platform already produces, plus a **lightweight history** of what's been generated. Today report generation is scattered (per-run drawer, Compliance tab, agent views) and nothing is recorded. This gives one place to generate from and an auditable log of who generated what, when.

**No artifact storage.** A history row stores only *metadata*; its download **re-generates on demand** by re-invoking the existing generator with the saved parameters. This avoids building a document-management system before the BAS platform itself is finished.

Maturity path (v1 here): `v1 hub + metadata history → v2 campaign reports → v3 executive summary → v4 artifact archive/retention`.

## Report types (honest mapping)

Only what we genuinely generate — **no Executive/Technical fiction**:

| Type | Generator (existing, untouched) | Inputs |
|---|---|---|
| **Posture report** | `GET /api/report/full/{html,pdf}?agentId=` | agentId, format (html/pdf) |
| **Audit pack** | `GET /api/report/audit-pack?agentId=` | agentId |
| **Compliance evidence** | `GET /api/compliance/report?framework=&agentId=&format=` | framework, agentId, format (html/pdf/csv) |

Per-run reports stay accessible from the run drawer (out of scope for the hub).

## Schema — `report_log` table

```
id            text PRIMARY KEY DEFAULT gen_random_uuid()::text
report_type   text NOT NULL              -- posture | audit | compliance
format        text NOT NULL DEFAULT ''   -- html | pdf | csv | ''
scope_label   text NOT NULL DEFAULT ''   -- human label, e.g. "WIN-HR-01" or "NIST · WIN-HR-01"
parameters    jsonb NOT NULL DEFAULT '{}'-- { agentId, framework?, format, campaignId:null } — forward-proof
source        text NOT NULL DEFAULT 'reports_hub'  -- reports_hub | run_drawer | compliance_page | campaign_page | api
status        text NOT NULL DEFAULT 'generated'    -- generated | failed
generated_by  text
generated_at  timestamptz NOT NULL DEFAULT NOW()
```

- **`parameters`** carries all generator inputs as JSON — new report types (e.g. campaign reports) need no schema change. `campaignId: null` is reserved now.
- **`source`** records where generation was initiated; v1 only ever writes `reports_hub`, but the field prevents a migration when other generators are instrumented later.
- **`status`** is `generated` in v1 (logging is synchronous-intent); reserved `failed` for when generation becomes synchronous/async. Costs nothing, avoids silent disappearance.
- The **download URL is NOT stored** — it is reconstructed from `report_type` + `parameters` by a shared helper, so generator route changes never break history rows.

Index: `idx_report_log_time (generated_at DESC)`.

## URL reconstruction

A **pure, unit-tested** helper `reportDownloadPath(reportType, params) (string, error)` builds the generator URL from type + parameters:

- `posture` → `/api/report/full/pdf?agentId=…` (or `/html`), per `params.format`
- `audit` → `/api/report/audit-pack?agentId=…`
- `compliance` → `/api/compliance/report?framework=…&agentId=…&format=…`

Used by both `POST` (immediate download) and `GET` (each history row's download), so the URL logic lives server-side in one place and is never persisted.

## API

Reads + generate logging = **viewer+** (reports are read-only evidence).

- **`POST /api/reports`** — body `{reportType, format, agentId, framework?}`. Validates (posture/audit need `agentId`; compliance needs `framework`+`agentId`; valid type/format), builds `parameters` (+ `campaignId:null`), computes `scope_label`, inserts a `report_log` row (`source=reports_hub`, `status=generated`, `generated_by` from auth), and returns `{id, downloadPath}`. The generator endpoints are not called here — the client opens `downloadPath`.
- **`GET /api/reports`** — recent history (newest first, limit 100); each row includes a freshly-reconstructed `downloadPath`.

## Frontend — Reports page

New **Reports** nav item (Visibility group). Page:

- **3 type tiles** — Posture report · Audit pack · Compliance evidence — each opens a small **Generate** modal: pick agent (+ framework + format for compliance) → `POST /api/reports` → open the returned `downloadPath` in a new tab → refresh history.
- **Generated reports** history table: **Report (type) · Scope · Format · Generated by · Generated at · Status · Download**. (Status sits before Download per the review.) Download re-opens the reconstructed path. Dropped vs the mockup: **score** and **pages** (can't be produced honestly without generating first).

## Testing

- Pure unit test for `reportDownloadPath` (each type, missing-param errors).
- `internal/api` validation is covered via the path builder; no real/prod-DB test.

## Non-goals (v1)

Stored artifacts / retention, executive-summary or technical report types, scheduled reports, capturing non-hub generations (run drawer / Compliance tab) into history, campaign reports, and score/page metadata. All are later maturity steps; `parameters_json` + `source` + `status` are in place so they land without migrations.
